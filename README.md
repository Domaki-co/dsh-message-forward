# dsh-message-forward (DSH 会话消息与结果提取转发插件)

专为解决“多会话上下文隔离”、“避免上下文过长污染下游模型”打造的微信风格跨会话即时转发与结果提取插件。

## 为什么需要它？（痛点场景）

在长时间执行复杂任务时，会话中往往包含大量的试错、文件检索、冗长思考过程，导致上下文急剧膨胀。对于上下文窗口较小或对长上下文敏感的模型，直接继承整个会话极易导致模型幻觉、格式混乱或指令遵循能力下降。

本项目支持**精准提取其他会话的部分关键产出（纯净结果、特定代码块、多条消息批量按序合并）**，将其作为独立干净的输入传递给新会话或下游任务会话。

## 核心特性

1. **微信风格多条批量选择与合并转发（🆕 新增）**
   - **长按 2 秒进入多选**：在任意转发按钮（模型回复或用户提问）上按住鼠标左键 2 秒，将展示动态环形倒计时并触发多选模式，自动勾选当前消息。
   - **微信式消息勾选框**：进入多选后，每条消息（用户提问或模型产出，含其附带的图片）左侧浮现圆圈勾选框，点击即可自由勾选/反选。
   - **严格按照原文时间先后顺序合并**：不论用户是以何种顺序点击勾选，提取合并时系统**严格按照对话在时间线中的原始上下先后顺序**排列（用户先发图、后发文字，或多轮问答，全部按真实时间流排布），绝无乱序。
   - **图文混排一并保留**：文字和多张图片分散在多条消息中时，全部自动聚合打包，一并作为多模态输入投递给下游新会话。
   - **底部浮动操作条**：微信同款底部毛玻璃控制条，实时显示「已选 N / M 条」，支持「全选」、「清空」、「退出 (Esc)」以及「合并转发」。
   - **快捷选择面板（🆕）**：多选状态下点击工具条上的「已选 N / M 条」，直接展开消息清单，
     每条带**角色徽章**（绿色「用户」/ 蓝色「模型」）+ 序号 + 摘要，**每段最多 150 字符**
     （超出截断加省略号，仅影响显示，不影响实际转发内容）。点击条目即可勾选/反选，
     **不必再滚动到消息本身**——长回答、长会话下尤其有用。面板内列表独立滚动
     （`max-height: min(300px, 38dvh)`），不会把工具条顶出视口；`Esc` 先收面板、再退出多选。

2. **精准单条/局部结果提取（避免上下文污染）**
   - **单回复直接转发**：每条模型回复下方均有「提取并转发」按钮（短按直接转发单条）。
   - **代码块一键提取（⚡ 仅提取代码块）**：弹窗内一键自动过滤所有解释性文字，仅保留核心 Markdown 代码块。

3. **弹窗内直接修剪与模板包装**
   - 弹窗内文本框**直接可编辑**，发送前可随手精简字数、调整格式。
   - **快捷加工模板**：
     - `+ 作为参考背景`：自动附加「以下是上游会话产出结果，请作为参考背景...」
     - `+ 作为任务输入`：自动附加「请基于以下上游结果，继续执行后续任务...」
     - `⚡ 仅提取代码块`：一键萃取代码块。
     - 来源标记可选开闭，默认纯净输出。

4. **三种投递模式**
   - **直接发送并跳转**：直接向目标会话投递 prompt，并自动切换主视图到目标会话。
   - **静默发送**：在后台直接投递到目标会话，不打扰当前会话浏览，附带 Toast 反馈。
   - **填入草稿并跳转**：切换到目标会话并将内容预填至输入框（Composer），供用户做最后的提示词组织后敲回车发送。

5. **一键新建干净会话**
   - 目标选择默认提供「新建独立空白会话」，一键在新会话开始干净的下游工作，彻底告别上下文爆炸。

6. **多模态图片支持**
   - 自动提取并转换消息内的图片资源为标准 Base64 载荷，文字与图片完美组合交付。

## 开发与测试

```bash
node tests/run.mjs        # 4 个套件、119 项断言
```

回归测试基于从 `app.asar` 提取的真实 DSH DOM 契约（类名与 `data-*` 属性）在 jsdom 中复现，
覆盖单条提取、多选合并、摘要截断、主题 token 有效性、弹窗自适应、以及多选装饰器的挂载与还原。详见
[tests/README.md](tests/README.md)。

### 已知的 DOM 契约依赖

DSH 的聊天行是**两层**结构，提取逻辑必须按行级（`[data-chat-flow-kind]`）而不是
`previousElementSibling` 回溯，否则只能看到尾行自己的操作按钮：

- 行级：`div[data-chat-flow-kind][data-chat-turn][data-chat-flow-key]`
- 尾行：`div[data-turn-tail]`（是上面那行的**子元素**，转发按钮就挂在这里）

正文只从 `data-chat-flow-kind="assistant-step"` 的行取，避免把用户消息或
「已思考 N 秒」的折叠行混进转发内容。

### 思考链为什么必须按属性排除

DSH 的 `AssistantMarkdown` 会把同一个 `assistant-step` 渲染**两次**，靠 `groupPart` 分流：

- `groupPart="reasoning"`：只含 reasoning 块的行（折叠态被打上 `hidden`）
- `groupPart="response"`：含 text 块的正式回答行

官方 copy 按钮取的是 `assistantText(closing.blocks)`——只拼接 `kind === "text"` 的块，
天然不含 reasoning / tool-call。插件在 DOM 侧对齐这个语义，排除三类节点：

- `[data-chat-group-part="reasoning"]`：思考链分组行
- 带 `hidden` / `data-turn-process-hidden` 的行：被折叠的过程成员
- `[data-variant="think"]`、`[data-turn-process-inline]`、
  `[data-markdown-variant="compact"]`：思考链根节点、内联包装、思考链专用的紧凑
  markdown 变体（正文用的是默认 `body` 变体）

**关键陷阱**：`innerText` 对 `hidden` 子树返回空串，而 `textOf` 的 `textContent` 兜底
会把折叠中的思考链正文重新捞回来——这正是「转发里混进思考链」的直接原因。因此判定必须
走属性，不能依赖构建期哈希类名，也不能依赖可见性。

### 弹窗自适应

primitives 的 `Modal` 卡片是 `width:min(380px,100%)` 且没有 `max-height`，内容一多就顶出
窗口。插件通过 `className` / `contentClassName` 挂上自己的类（`.dsh-mf-dialog` /
`.dsh-mf-content`）接管尺寸，并按官方注释的约定封顶（消费方用 `max-height:100%`，而不是
自己算视口）：

- 卡片：`width:min(720px,100%)` + `max-height:100%`
- 正文区：`dialog > content > body` 全链 `min-height:0` 接上 flex 收缩链，内部滚动；
  另留 `calc(100dvh - 240px)` 兜底
- 编辑框 / 会话列表：`min(300px, 32dvh)` / `min(240px, 26dvh)` 跟随视口
- 选择器写成 `.dsh-mf-dialog.dsh-mf-dialog` 以稳定压过 primitives 的同名规则，
  不依赖两边 `<style>` 的注入顺序
